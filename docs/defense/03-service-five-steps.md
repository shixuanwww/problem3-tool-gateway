# 模块 3：五步决策与优先级

**代码**：`server/gateway/service.ts` → `handleToolCall`

## 1. 这段在干什么

`POST /tool-calls` 的唯一决策入口：按题面给定的**五步顺序**走完，产出 `allow` / `require_approval` / `deny`，并**无论哪个分支都写一条审计**。

## 2. 关键设计决策 + 为什么

| 决策 | 为什么 |
|---|---|
| **五步顺序不可乱**（题面给定） | 1 查工具 → 2 校验参数 → 3 检查资源范围 → 4 按策略决定 → 5 记录 |
| 🔴 **决策优先级：未知工具 → 参数非法 → 越界 → 需确认 → 执行** | 题面场景 3 要求 `delete_note(path="../../config.json")` 必须是 `deny`。如果先判 `requiresApproval`，它会变成"等待确认"，**场景 3 直接演示不出来**。所以步骤 1–3 的 `deny` 永远压过步骤 4 的 `require_approval`（用例 12 专门验证） |
| `delete_note` 标 `requiresApproval: true` 与"越界必须 deny"**不冲突** | 合法路径（`draft.txt`）走 `require_approval` —— 因为题面把 `delete_note(path="draft.txt")` 当作**用户确认**的例子；越界路径在步骤 3 就被拒，**根本走不到步骤 4** |
| 步骤 4 内部**先查执行记录，再查待确认记录** | 先看"这件事是不是已经做过了"（副作用是否已发生），再看"用户之前对这个调用的结论是什么"。顺序反了会出现"拿着已批准记录去重复执行" |
| 复用旧结论时，`decision` 回 `allow` 而不是 `require_approval` | 功能上的理由：题面规定 Client 收到 `allow` 才"展示工具执行结果"，收到 `require_approval` 就要去弹确认。一个**已经执行完**的调用如果回 `require_approval`，Client 会去等一个永远不会来的用户操作 |
| `status` 允许 `failed`（题面只给了三个 status） | 执行期错误 / 超时需要如实反映。`decision` 仍是三值之一，`status` 描述执行结果 —— 两者维度不同，混在一起会丢信息 |
| 审计在**每个分支**都写，且**一次请求恰好一条** | 题面第 8 项测试要求"每次决定与执行均存在审计记录"。把审计写在函数出口统一处而不是散落在分支里，就不会漏 |

## 3. 可能被追问的问题

**Q：为什么"越界"要优先于"需要确认"？反过来会怎样？**
A：反过来的话，`delete_note("../../config.json")` 会返回 `require_approval` 并生成一条待确认记录 —— 用户一旦点了"确认"，Gateway 就会去执行这个**本该被拒绝**的越界删除。也就是说：**用户的确认不能成为绕过沙箱的授权**。沙箱是硬边界，必须在"要不要问用户"之前就生效。

**Q：`deny` 的 HTTP 状态码为什么是 400？**
A：题面没有规定 HTTP 码。本项目口径（`PLAN.md` §11）：越界 / 未知工具 / 参数非法 = `400`（请求本身有问题）；确认类状态冲突（过期、已用、换用户、已拒绝、工具或参数变化）= `409`。**关键点**：这两种响应体都是**完整的 `ToolCallResponse`**，所以 Client 和测试必须"先解析响应体、再看状态码"，写成 `if (!res.ok) throw` 会把 `reason` 全丢掉。

**Q：同一个 `call_id` 用不同参数再发一次会怎样？**
A：`deny`，原因 `'工具或参数发生变化'`（HTTP 409），**既不执行也不新建待确认记录**。这是题面"工具或参数发生变化 → 拒绝"的直接落点。它隐含一条不变量：**`call_id` 与 `(tool_name, arguments)` 一一绑定**，改工具或改参数就必须换新的 `call_id`；只有"同一组合的两阶段重发"才复用同一个 `call_id`。

**Q："步骤 5 记录本次决定"和"写审计"是一回事吗？**
A：是同一件事。步骤 5 的产物就是 `server/data/audit.jsonl` 里那一行 + 终端打印那一行。

**Q：如果 `arguments` 里塞了 `path` 之外的东西呢？**
A：`additionalProperties: false` 会拦掉。但注意：这条规则来自**工具自己的 schema**，不是全局硬编码 —— 将来某个工具有额外可选字段，只要改 schema，不用改 service。
