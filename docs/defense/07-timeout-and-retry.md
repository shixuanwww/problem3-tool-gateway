# 模块 7：超时与安全重试

**代码**：`server/gateway/executor.ts`、`server/tools/*.ts`

## 1. 这段在干什么

执行工具、给执行加超时，并把"这次调用到底做没做过"落成**执行记录**，从而让"超时后能否安全重试"有判据。

## 2. 关键设计决策 + 为什么

| 决策 | 为什么 |
|---|---|
| 执行**前**先写 `started` 意图记录，成功后追加 `success` | 超时/崩溃时留下的唯一线索就是这条 `started`。"先写意图再执行"是经典的 WAL 思路：**宁可多留一条假线索，也不能少留一条真线索** |
| 同一 `call_id` 有多条记录时，取 `started_at` **最大**的一条判状态 | 这样才能区分"只写了意图（可能已执行）"与"明确成功" |
| 已有 `success` ⇒ **绝不重跑**，直接返回已存结果 | 这条**任何情况都不放宽**。副作用已经发生，重跑就是第二次副作用 |
| 无 `success` 且**幂等** ⇒ 可安全重试 | `read_note` 只读；`delete_note` **目标状态一致**（见下） ⇒ 重试不会造成额外影响 |
| 无 `success` 且**非幂等** ⇒ **不自动重试**，转人工确认 | `send_email` 重试会发出第二封邮件。这是 README 第 5 问的核心答案 |
| `send_email` 的 `send_email`（`message_id`）由 Gateway 生成、**不进 `arguments`** | 否则同一份用户意图每次算出不同 `argument_hash`，绑定与幂等判定全部失效 |
| 🔴 `delete_note` 把 **ENOENT 视为删除成功**，统一返回 `{deleted: path}` | 否则"第一次删成功但响应丢了 → 重试时文件已不存在 → 报 ENOENT 错误" ⇒ `idempotent` 这个标记就不成立，README 第 5 问的答案也跟着塌 |
| 超时用 `withTimeout(promise, ms)` 包装，不 `kill` 底层任务 | 工具是本地文件/写文件，本身很快就会结束；真去"取消"需要工具自己配合（AbortSignal），对本题是过度设计。**但要在答辩里说清这个限制**：超时只保证"调用方不再等"，不保证"底层没继续跑"——这正是为什么超时后要按"可能已执行"保守处理 |
| `executeTool` 接受**可注入的工具实现表** | 用例 19 的"超时桩"靠它注入。🔴 不用环境变量开关（本项目禁止引入 `.env` / 环境变量） |
| `allowAfterTimeout` 只由 `/decision` 传入 | 否则"转人工确认"会变成**死锁**：用户确认了，执行时又因为"有超时记录"被拦住，永远发不出去。人工的显式确认是唯一能越过这道闸门的钥匙 |

## 3. 可能被追问的问题

**Q：超时到底说明了什么、没说明什么？**
A：只说明"调用方在 N 毫秒内没等到结果"。**不说明**底层有没有执行完 —— 可能是没跑，也可能是跑完了但响应丢了（网络/进程被 kill）。所以默认**按"可能已执行"处理**，这才是保守而正确的选择。这也是为什么第 3 步的判据不是"超时了所以要重试"，而是"**没有 success 记录**，再看幂等性"。

**Q：那 `read_note` 超时了为什么可以直接重试？**
A：因为它是**只读**的 —— 重试最坏结果是"多读一次文件"，没有副作用。用例 19 里 `read_note` 第一次慢（超时）、第二次快（成功），断言第二次 `decision=allow / status=executed` 且 `readAttempts === 2`（确实重试了）。

**Q：`delete_note` 标记成 `idempotent` 有什么风险？**
A：风险在于"删 A 之后又建了一个新的 A"。在本题沙箱里不存在这个场景（没有并发写者），所以"目标状态一致"成立。**答辩时要主动说这个前提**：如果目标是可变的（比如"把账户余额减 10"），ENOENT 那套就不适用，必须换业务级幂等键。

**Q：为什么 `src/tools` 里报错不写终态记录？**
A：因为错误（比如 read_note 目标不存在）**不改变**"这次调用可能已经产生了副作用"这个判断。留着 `started` ⇒ 后续按"可能已执行"处理 ⇒ 幂等工具仍可重试、非幂等工具仍需人工确认。写一条 `error` 反而会让状态机多一个分支而没有信息增益。

**Q：跨进程怎么办？**
A：执行记录现在是 `server/data/executions.jsonl`，**同进程内读得到、跨进程也读得到**（因为它落盘了）—— 但**并发写**没有锁，多实例下会互相干扰。生产做法是把"调用意图 + 结果"落到有唯一约束的存储，或直接用外部系统的幂等键（邮件服务的 `Idempotency-Key`）。
