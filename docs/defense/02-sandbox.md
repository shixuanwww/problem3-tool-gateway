# 模块 2：沙箱四道闸门

**代码**：`server/gateway/sandbox.ts`（另外 `server/tools/*.ts` 里每个工具都自己再走一遍 —— 纵深防御）

## 1. 这段在干什么

把请求里不可信的 `path` 参数，解析成一个**保证落在白名单目录内**的绝对路径；任何越界都返回拒绝原因。

## 2. 关键设计决策 + 为什么

| 决策 | 为什么 |
|---|---|
| **闸门 0：拒绝控制字符（含 NUL）** | JSON 里可以用 `\u0000` 表达 NUL；它不会被 `path.resolve` 拆掉，会一路走到 `fs` 层才抛错 —— 结果是 `decision=allow / status=failed`（策略说"可以"，执行才炸）。这类路径必须在策略阶段就 deny |
| **闸门 1：拒绝绝对路径**（POSIX 绝对路径 / 盘符 / UNC / 前导分隔符） | 题面点名的第一种绕过方式 |
| **闸门 2：在归一化之前按段判"点/空格段"与 `:`** | 题面点名的第二种绕过方式（`../`）。在归一化之前判，因为先 `path.resolve` 的话 `..` 就被"吃掉"了（`a/../../b` 会变成看似合法的路径）。**不只看开头**：只判 `startsWith('..')` 会漏掉 `a/../../b`。另外两条是 2026-10-11 第三轮补的：① **只由点/空格组成的段**（`.. ` / `...` / `....`）——Windows 会规范化段末尾的点与空格，语义上等价于 `..`，而它们在任何平台都不是合法文件名（`.` 单独放行，所以 `./todo.md` 仍可用）；② **段内出现 `:`** —— Windows 的 ADS 分隔符，`todo.md::$DATA` 能绕过"只读这个文件"的直觉（实测改前返回 `200 allow executed`） |
| **闸门 3：先做字符串前缀再做 realpath** | 题面点名的第三种绕过方式（符号链接）。字符串前缀是廉价的防御性检查；realpath 才是**授权判定**，因为它能解开符号链接 |
| 🔴 `REPO_ROOT` 由**模块位置**推导，禁止 `process.cwd()` | 从仓库根启动、从任意目录启动、被别的模块 import —— 三种情况必须得到同一个仓库根。用 `cwd` 的话，从 `server/` 目录启动就会算错根，前缀比对直接失效（而且是**静默**失效） |
| realpath 遇到"文件不存在"时，对**最近的已存在父目录**做 realpath 再拼回剩余段 | `delete_note` 的目标本来就可能不存在；如果直接对不存在的路径 realpath，Node 会抛 `ENOENT`，那就得写一堆特判。这个写法对"存在/不存在"统一处理 |
| 前缀比对要求**严格在其内**（`t !== root && t.startsWith(root + sep)`） | 否则 `path="."` 会解析成白名单目录自己，`delete_note(path=".")` 就能把整个目录端掉 |
| 工具内部**再走一遍** `resolveInSandbox` | 纵深防御：即使将来有人从别的入口调工具、绕过了 service 的第 3 步，工具本身也不会越界 |

## 3. 可能被追问的问题

**Q：Windows 上 `path.isAbsolute('/etc/passwd')` 是什么结果？**
A：`true`（Node 在 win32 上把前导 `/` 也当绝对路径）。但我不只依赖它 —— 额外还有一道 `startsWith('/') || startsWith('\\')`，以及盘符正则 `^[A-Za-z]:` 和 UNC 判断 `^\\\\`。四者取并集。

**Q：符号链接用例你怎么证明真的生效了？**
A：`tests/basic.test.ts` 用例 6 + `tests/sandbox.test.ts` 的闸门 3 直测。本机（Windows）**建不了文件符号链接**（需开发者模式/管理员），所以先试文件符号链接、失败就**退化用目录 junction**（Windows 上不需要权限），指向一个外部目录，读 `link/secret.txt` —— 同样被 realpath 挡下。两条都建不了时，测试会**明确打印"未在本机得到实证"**，不会静默算通过。

**Q：为什么第 3 道要做 realpath 而不是用 `path.resolve` 归一化就够了？**
A：`resolve` 只做**字符串**层面的归一化，它不会去问文件系统"这个路径实际指向哪"。符号链接是**文件系统**的事实，只有 `realpath` 能拿到。所以闸门 0–2 是"看清你写了什么"，闸门 3 是"看清它到底是谁"。

**Q：`realpathSync(rootAbs)` 失败（白名单目录不存在）怎么办？**
A：返回拒绝。宁可拒绝也不能放行 —— 白名单目录不存在说明环境被破坏了，此时任何"放行"都是不可预期的。

**Q：`sandbox/notes/link` 是仓库里的一个文件吗？**
A：**不是**。它**不落盘、不进 git、`reset.ts` 也不建** —— 因为 Windows 上签出符号链接会失败、且创建它需要权限。它由测试**动态创建并在 `finally` 里删除**。（这条口径写在 `PLAN.md` §5 阶段 A 第 6 条与 §11 账本里。）
